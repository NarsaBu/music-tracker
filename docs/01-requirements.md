# 01 — Требования

## 1. Цель

Получать уведомление, когда у интересующего исполнителя выходит (или анонсируется) новый релиз нужного типа, без ручного мониторинга.

Приложение **однопользовательское** (личный инстанс): регистрации, учётных записей и входа нет.

## 2. Термины

| Термин | Значение |
|--------|----------|
| **Исполнитель (Artist)** | Сущность MusicBrainz, идентифицируется MBID (UUID). |
| **Релиз-группа (Release Group)** | Абстрактный «альбом/сингл» в MusicBrainz, объединяющий все издания. **Единица отслеживания** в системе. |
| **Релиз (Release)** | Конкретное издание (CD, винил, digital). Не отслеживается, чтобы переиздания не порождали дубли уведомлений. |
| **Primary type** | Album, Single, EP, Broadcast, Other. |
| **Secondary type** | Compilation, Soundtrack, Spokenword, Interview, Audiobook, Audio drama, Live, Remix, DJ-mix, Mixtape/Street, Demo, Field recording. |
| **Artist credit** | Список исполнителей релиз-группы с соединительными фразами (`" & "`, `" feat. "`). |
| **Роль в credit** | `main` — исполнитель первый в credit; `collaboration` — равноправный соавтор (`&`, `and`, `x`, `,`, `/`); `featured` — приглашённый (`feat.`, `ft.`, `featuring`, `with`). |
| **Подписка** | Отслеживаемый исполнитель с индивидуальными настройками. |
| **Baseline** | Снимок всех релиз-групп исполнителя на момент подписки; по ним уведомления не отправляются. |
| **Дайджест** | Одно письмо со всеми новинками, накопленными с прошлой отправки. |

## 3. Пользовательские сценарии

| ID | Я хочу… | Чтобы… |
|----|---------|--------|
| US-1 | найти исполнителя по имени и выбрать нужного из списка (с уточнением: страна, годы, disambiguation) | подписаться на правильного исполнителя среди тёзок |
| US-2 | импортировать список исполнителей из файла | не добавлять их по одному |
| US-3 | вручную разрешить неоднозначные совпадения после импорта | не подписаться на чужого тёзку |
| US-4 | видеть список подписок и отписываться | управлять отслеживанием |
| US-5 | выбрать типы релизов для уведомлений (глобально и переопределить для исполнителя) | не получать уведомления о ненужных компиляциях и т.п. |
| US-6 | для каждого исполнителя решать, учитывать ли релизы, где он приглашённый участник (feat.) | узнавать о гостевых появлениях любимых артистов, но не у всех |
| US-7 | получать email-дайджест ежедневно или еженедельно | узнавать о новинках без захода в приложение с удобной частотой |
| US-8 | подписаться на персональную RSS/Atom-ленту | читать новинки в RSS-ридере |
| US-9 | видеть ленту найденных релизов в веб-интерфейсе | просматривать историю новинок |
| US-10 | запустить проверку вручную | не ждать ежедневного запуска |

## 4. Функциональные требования

### FR-1. Интеграция с MusicBrainz
- FR-1.1 Поиск исполнителей (`/ws/2/artist?query=`), выдача: имя, disambiguation, тип, страна, годы активности, score.
- FR-1.2 Получение релиз-групп исполнителя (browse `/ws/2/release-group?artist=&inc=artist-credits`), с пагинацией.
- FR-1.3 Соблюдение правил API: ≤ 1 запрос/сек, осмысленный `User-Agent`, повторы при 503.
- FR-1.4 Обложки через Cover Art Archive (ссылкой).

### FR-2. Управление исполнителями
- FR-2.1 Добавление по результату поиска (по MBID).
- FR-2.2 Добавление по прямой ссылке/MBID MusicBrainz.
- FR-2.3 Импорт из файла:
  - форматы: `.txt` (одно имя или MBID на строку), `.csv` (колонки `name`, опционально `mbid`, `include_featured`);
  - строки с MBID добавляются сразу;
  - имена ищутся через API; при единственном совпадении с высоким score (≥ 95 и отрыв от второго ≥ 10) — автодобавление, иначе — в очередь ручного выбора;
  - импорт выполняется асинхронно, прогресс доступен через API.
- FR-2.4 Удаление подписки.
- FR-2.5 При подписке выполняется baseline: существующие релиз-группы помечаются известными без уведомлений; исключение — релизы с датой не старше `N` дней (FR-3.4), они попадают в ленту как новинки.

### FR-3. Проверка новых релизов
- FR-3.1 Планировщик запускает синхронизацию ежедневно (время настраивается, по умолчанию 06:00 UTC).
- FR-3.2 Ручной запуск синхронизации (для всех подписок или одного исполнителя).
- FR-3.3 Новый релиз = релиз-группа, MBID которой ранее не встречался у этого исполнителя.
- FR-3.4 Защита от «старых новинок»: релиз-группа, добавленная в MusicBrainz задним числом (дата первого релиза старше `N` дней; `N` задаётся в настройках, по умолчанию 90), не считается новинкой, а молча добавляется в каталог.
- FR-3.5 Релизы с датой в будущем считаются анонсом; настройка «уведомлять об анонсах» (по умолчанию — да).

### FR-4. Фильтры релизов
- FR-4.1 Множество разрешённых primary types (по умолчанию Album, EP, Single).
- FR-4.2 Множество исключаемых secondary types (по умолчанию Compilation, DJ-mix, Interview, Spokenword, Audiobook, Audio drama, Demo, Field recording).
- FR-4.3 **Featuring**: флаг `include_featured` — учитывать ли релиз-группы, где исполнитель имеет роль `featured`. Глобальное значение по умолчанию — выкл.; задаётся для каждой подписки (при добавлении, импорте и в настройках исполнителя).
- FR-4.4 Релизы с ролью `main` и `collaboration` учитываются всегда.
- FR-4.5 Любой фильтр (типы, featuring) можно переопределить для конкретной подписки; `null` = использовать глобальные настройки.
- FR-4.6 Фильтр применяется при создании уведомлений; каталог хранится полностью (смена фильтра не требует повторной загрузки).

> Ограничение: учитывается featuring только на уровне релиз-группы (`"Artist A feat. Artist B"` в credit альбома/сингла). Гостевое участие в отдельном треке чужого альбома без упоминания в credit релиз-группы не отслеживается (потребовало бы обхода recordings — см. roadmap).

### FR-5. Уведомления
- FR-5.1 Каналы: Email, RSS/Atom. Каждый включается/выключается отдельно.
- FR-5.2 Email-дайджест: одно письмо со всеми накопленными новинками (HTML + plain text).
- FR-5.3 Частота дайджеста: `daily` или `weekly` (выбор дня недели) + время отправки и часовой пояс. По умолчанию — ежедневно в 09:00.
- FR-5.4 Если с прошлого дайджеста новинок нет — письмо не отправляется.
- FR-5.5 Адрес получателя задаётся в настройках; кнопка «Отправить тестовое письмо».
- FR-5.6 RSS: лента по секретному токену (`/feeds/{token}.atom` и `.rss`), токен можно перевыпустить. Лента обновляется сразу после синхронизации, независимо от расписания дайджеста.
- FR-5.7 Гарантия доставки «at-least-once» через outbox, повторы с экспоненциальной задержкой.
- FR-5.8 Один релиз — не более одного уведомления в каждом канале.

### FR-6. Доступ
- FR-6.1 Аутентификации нет: приложение разворачивается в доверенной сети; доступ снаружи защищается reverse proxy.
- FR-6.2 RSS-фиды адресуются секретным токеном, который можно перевыпустить.

## 5. Нефункциональные требования

| ID | Требование |
|----|------------|
| NFR-1 | Масштаб: 1 пользователь, до 2 000 исполнителей. При 1 RPS полный прогон ≈ 45 мин. |
| NFR-2 | Rate limit к MusicBrainz — глобальный на процесс, не превышается ни при каких сценариях (импорт + синк одновременно). |
| NFR-3 | Идемпотентность: повторный/прерванный прогон не создаёт дублей уведомлений. |
| NFR-4 | Наблюдаемость: структурированные логи (`slog`, JSON), `/healthz`, `/readyz`; метрик и дашбордов нет — достаточно логов в Portainer. |
| NFR-5 | Безопасность: секреты только через env; RSS-токен ≥ 128 бит энтропии. |
| NFR-6 | Тестируемость: use cases покрыты unit-тестами с моками портов; адаптеры — интеграционные тесты (testcontainers для Postgres, httptest для MusicBrainz). |
| NFR-7 | Развёртывание: Docker Compose (backend, frontend, postgres, mailpit для dev). |
| NFR-8 | Конфигурация через переменные окружения (12-factor). |
| NFR-9 | UI в стиле скевоморфизма, при этом доступный: контраст WCAG AA, управление с клавиатуры, `prefers-reduced-motion`. См. [10-design.md](10-design.md). |

## 6. Вне рамок MVP

- Отслеживание лейблов.
- Featuring на уровне отдельных треков.
- Многопользовательский режим.
